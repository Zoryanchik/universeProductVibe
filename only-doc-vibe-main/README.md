# OnlyDoc — старт для vibe-кодингу 🚀

Це інструкція для тих, хто хоче змінювати проєкт за допомогою ШІ (Claude Code або Cursor), **не будучи розробником**. Тут усе пояснено простими словами, крок за кроком. Якщо ви ніколи не запускали проєкти — нічого, ви впораєтесь.

> 🆘 **Застрягли? Питайте тьютора.** Сьогодні тьютори на звʼязку й допоможуть із будь-яким кроком — від встановлення до першої фічі. Не соромтеся писати навіть із дрібним питанням: напишіть у чат вашої групи або тьютору напряму.

---

## Що це за проєкт

**OnlyDoc** — це вебсайт із безкоштовними інструментами для роботи з документами: конвертація, стиснення, підпис PDF тощо. Люди приходять із пошуку (Google), користуються інструментом безкоштовно, а потім частина з них купує підписку.

Технічно сайт зроблено на **Astro + React**. Вам не треба це вивчати — просто знайте, що:
- сторінки складаються з окремих «блоків»;
- блоки розкладені по чітких «шарах» (про це нижче, у розділі [Правила](#правила));
- ШІ вже знає ці правила — треба лише користуватися підказками (скілами).

## Крок 1. Що встановити (робимо один раз)

### Node.js (обовʼязково)
Це «двигун», який запускає проєкт.
1. Відкрийте [nodejs.org](https://nodejs.org).
2. Завантажте версію **LTS** (велика зелена кнопка). Потрібна **версія 20 або новіша**.
3. Встановіть як звичайну програму (тиснете «Далі» → «Далі» → «Готово»).

> Перевірити, що встановилось: відкрийте **Термінал** (на Mac — програма «Terminal», на Windows — «PowerShell») і напишіть `node -v`. Має зʼявитися щось на кшталт `v20.11.0`.

### Git (обовʼязково — щоб завантажити проєкт)
Це програма, якою завантажують код із GitHub.
- **Найпростіше:** встановіть [**GitHub Desktop**](https://desktop.github.com) — зручний застосунок із кнопками, тут же увійдете у свій акаунт GitHub.
- **Або** консольний [**Git**](https://git-scm.com/downloads) (якщо любите термінал).

> Перевірити: у Терміналі напишіть `git -v` — має зʼявитися версія.

### Доступ до проєкту
Попросіть команду додати вас до приватного репозиторію **`universe-forma/only-doc-vibe`** (і увійдіть тим самим акаунтом у GitHub Desktop). Токени, паролі до бібліотек — **не потрібні**, усе вже вбудовано всередину.

## Крок 2. Завантажити проєкт

**Через GitHub Desktop (найпростіше):**
1. Відкрийте сторінку репозиторію `universe-forma/only-doc-vibe`.
2. Зелена кнопка **Code** → **Open with GitHub Desktop** → **Clone**.
3. Запамʼятайте папку, куди він збереже проєкт.

**Або через термінал** (якщо встановили консольний Git):
```bash
git clone https://github.com/universe-forma/only-doc-vibe.git
cd only-doc-vibe
```

## Крок 3. Запустити — одна команда

У Терміналі зайдіть у папку проєкту й напишіть:

```bash
npm run vibe:up
```

Ця команда робить усе сама, **прямо в цій папці**:

1. встановлює залежності **без жодного токена** — приватні бібліотеки вже вбудовані в проєкт, окремо логінитися нікуди не треба;
2. запускає локальний сервер;
3. сама відкриває браузер на сторінці `http://localhost:4322`.

Перший запуск триває 1–2 хвилини (качає файли). Коли відкриється вкладка браузера з сайтом — усе готово, можна працювати. Щоб зупинити — натисніть у Терміналі `Ctrl + C`.

> **Важливо:** ви працюєте прямо у клонованій папці — нічого нікуди не копіюється. Сайт бачите тільки ви, на своєму компʼютері.

## Крок 4. Як щось міняти за допомогою ШІ

Головне правило — **спочатку думаємо, потім робимо**:

1. **Плануємо найсильнішою моделлю.** Увімкніть режим планування й опишіть, що хочете. Сильна модель складе план — які файли чіпати, що додати. На цьому кроці код ще **не** пишеться.
2. **Реалізуємо швидшою (дешевшою) моделлю.** Перемкніть модель і дайте їй виконати готовий план крок за кроком.

Так виходить і швидше, і дешевше, і надійніше, ніж робити все однією великою моделлю. Детальніше — [`docs/vibe/workflow.md`](docs/vibe/workflow.md).

### Готові підказки (скіли), які знають правила проєкту

Однаково працюють у **Claude Code** і в **Cursor** (ті самі назви):

| Скіл | Коли вмикати |
|------|--------------|
| `vibe-workflow` | перед будь-якою задачею — задає правильний порядок роботи |
| `add-feature` | коли додаєте нову фічу чи екран |
| `architecture-guard` | щоб ШІ не порушив архітектуру, поки пише код |
| `mock-data` | коли гіпотеза потребує бекенду, якого немає — підставити тестові дані |
| `preflight-check` | перед тим, як зберігати зміни (коміт) |

> 💡 **Тестуєте продуктову гіпотезу, а вона потребує бекенду?** Не чекайте доступу — попросіть ШІ «замокати дані» (скіл `mock-data`), і перевірте ідею на фейкових, але реалістичних даних. Деталі — [`docs/vibe/mock-data.md`](docs/vibe/mock-data.md).

## Правила

Проєкт побудований за **Feature-Sliced Design**: код розкладений по шарах, і шар може використовувати лише ті, що **нижче** за нього — ніколи навпаки:

```
app → pages-layer → widgets → features → entities → shared
```

Вам не треба це памʼятати напамʼять — скіл `architecture-guard` стежить за цим замість вас. Якщо цікаво глибше:

- [`docs/vibe/architecture.md`](docs/vibe/architecture.md) — шари, структура блоку, як називати файли.
- [`docs/vibe/add-feature.md`](docs/vibe/add-feature.md) — покроковий приклад, як додати нову фічу.
- [`docs/vibe/preflight.md`](docs/vibe/preflight.md) — що перевірити перед збереженням змін.

## Якщо щось пішло не так

- **`command not found: npm`** — не встановлений Node.js. Поверніться до [Кроку 1](#крок-1-що-встановити-робимо-один-раз).
- **`command not found: git`** — не встановлений Git / GitHub Desktop. Поверніться до [Кроку 1](#крок-1-що-встановити-робимо-один-раз).
- **Браузер не відкрився сам** — просто відкрийте вручну [http://localhost:4322](http://localhost:4322).
- **Порт зайнятий / сайт не відкривається** — можливо, проєкт уже запущений в іншому вікні Терміналу. Закрийте зайве вікно (`Ctrl + C`) і спробуйте знову.
- **Помилки про CMS / 401 у Терміналі** — це нормально для деяких сторінок; сайт усе одно відкриється. Якщо контенту зовсім немає — напишіть команді.
- **Нічого не допомогло** — скопіюйте текст помилки з Терміналу й попросіть ШІ («ось помилка, що робити»). Якщо не вийшло — **пишіть тьютору**, сьогодні вони на звʼязку й допоможуть швидко.
